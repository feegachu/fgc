# #480 해약환급금 합산 기간

계약 차월은 환급률표 조회와 표시용으로 유지한다. 합산 여부는 계약일부터 해지·실효 효력일까지의 경과기간으로 판정한다.
기준일 이하 사건을 효력시각·event_seq·사건 ID 순으로 해석한다. 현재 해지·실효 구간이 유지되는 경우에만 그 구간의 최초 TERMINATED/LAPSED 효력일을 서울 날짜로 읽고, 해당 효력일 이하 최신 금융 스냅샷을 선택한다. 부활 뒤에는 기준일 최신 스냅샷을 사용하고, 재실효하면 새로운 구간의 시작일을 사용한다. 실효 후 해지는 같은 구간이므로 최초 실효일을 유지한다.
미래 사건은 무시하며, 유지 중 계약은 검증 기준일에 해지한다고 가정한 모니터링을 유지한다.

ACTIVE ARBITRAGE 정책의 ARBITRAGE_REFUND_ADDITION_MONTHS와 ARBITRAGE_REFUND_ADDITION_BOUNDARY_INCLUSIVE를 사용한다.
데모 정책은 36개월·경계일 제외다. 정밀 경계일은 확정된 규제 해석이 아닌 프로젝트 정책이며 승인된 정책값으로 변경한다.
파라미터가 없거나 유효하지 않으면 REVIEW_REQUIRED로 남기고 임의 기본값을 적용하지 않는다. 누락은 POLICY_MISSING, 잘못된 날짜·기간·경계 값은 DATA_QUALITY로 구분한다.
V56 데모 마이그레이션은 기존 승인 정책을 변경하지 않고 새 버전으로 승계한다. 운영은 별도 정책 등록·승인이 필요하다.
기존 금융자료와 검증 이력은 변경하지 않는다. A1 시드의 원래 금융 스냅샷과 해지 사건은 모두 2026-08-20 기준이다.

영향: FUN-063 / ARB-W01 / 기존 차익거래 조회·수동·배치 API. API 응답 구조 및 테이블 DDL 변경 없음.

PR 미병합 데모 파일의 SQL 내용은 그대로 두고 V53.1에서 V56으로 번호를 올렸다. 최신 develop의 V55 적용 후에도 out-of-order 설정 없이 순서대로 실행하기 위한 조정이다. 기존 적용 완료 마이그레이션은 변경하지 않는다.

리뷰 보완 검증: 격리 PostgreSQL 17에서 차익거래 관련 88건 통과, 기존 화면 통합 테스트 1건 건너뜀. 부활 당일·이후 스냅샷, 재실효 후 구간 시작일, 실효→해지의 최초 실효일 유지, 미래 부활 무시, 동일 효력시각의 사건 순서와 정책 누락/오류 분류를 확인했다. 배포 서버나 공유 DB는 변경하지 않았다.

JDBC 비교 구현 보완 후 비교 테스트 5건, verifyPersistenceDependencies 및 bootJar/bootWar도 통과했다.
