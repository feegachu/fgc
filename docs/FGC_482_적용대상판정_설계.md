# #482 적용대상 판정

## 확정 동작
- 원수사→GA: 2021-01-01, GA→설계사: 2026-07-01 이후 체결 계약을 적용대상으로 판정한다.
- 적용 시작 계약일은 활성 룰셋과 독립적인 `CapApplicabilityPolicy`의 버전 있는 기준이다.
- 시행 전 계약: `NOT_APPLICABLE`, cap_rule_set_id 및 계산 금액·사용률은 null, 상세 산입 행은 없음.
- 시행 이후의 룰셋 누락은 CAP_004를 유지한다. 지급·증빙·귀속·정책버전의 다른 검증을 우회하지 않는다.
- 계약 등록/수정, 스케줄 생성/확정, 수동 재검증, 월·일일 배치, 지급확정에서 같은 판정·사유 저장을 사용한다.
- 사전검증은 같은 사유를 응답하지만 DB를 변경하지 않는다.
- 정상/주의/위반/검토필요 카드와 지급단계·설계사 모니터링 금액·건수와 월 검증의 CAP 검증 건수에서 비대상은 제외한다. CAP 목록/계약 상세에서 조회 가능하다.

## 사유 저장
`calculation_snapshot.applicability`:
- status: NOT_APPLICABLE
- scope: CONTRACT_PAYMENT_STAGE
- reasonCode: CONTRACT_BEFORE_EFFECTIVE_DATE
- reason: 적용대상 아님 — 시행 전 계약
- contractDate, paymentStage, effectiveContractDate, policyVersion, basisRefs

지급확정 스냅샷에는 해당 계약·단계의 후보 귀속 ID/귀속일/금액/사유 코드도 보존한다. 감사 로그는 판정 스냅샷과 연결된다.

## #479와의 관계
후보 귀속일이 초년도 밖인 사유는 계약 적용 여부와 분리한다. #479에서는 후보별 산입 제외 사유(`OUTSIDE_FIRST_YEAR`)와 기간 경계를 후보 스냅샷에 기록한다. 계약 전체를 비대상으로 변경하지 않는다. 이번 #482는 #479의 판정 변경을 포함하지 않는다.

## 병합 전 확인
- V50은 2026-10-13 사용자가 팀에 예약한 #482 번호다. 기존 임시 V45를 V50으로 변경했다. 공유되거나 적용된 migration은 수정하지 않는다.
- API 상태값 NOT_APPLICABLE 및 조건부 null 금액을 FE 담당에게 공유하고 api-change 라벨을 반영한다.
- 기존 POLICY_MISSING 검토 건은 자동 일괄 종료하지 않는다. 현재 재검증과 과거 검토 이력 처리 범위를 구분한다.

## 변경 파일 흐름
1. Controller: 기존 지급·CAP·계약 API 경로를 유지한다.
2. Service: `CapApplicabilityPolicy`가 시행 기준을 판정하고 `CapCalculatorImpl`이 비대상 결과·사유를 만든다. `CommissionPaymentServiceImpl`은 룰셋 게이트 전에 같은 판정을 적용하고 후보 귀속 사유를 저장한다. `CapCheckBatchAdapter`는 결과 없는 건을 조용히 버리지 않는다.
3. Repository: `CapCheckWriteRepository`의 기존 저장 계약을 재사용한다. `CapCheckQueryRepository`는 비대상을 목록에 노출하고 모니터링 집계에서 제외한다. V50은 비대상 저장 형태와 기존 정상 결과의 필수값을 DB에서 검증한다.
4. DTO: `CapCalculationResult`, `CapCheckItemResponse`, `TransactionPrecheckResponse`에 비대상 계산값의 null 의미와 사유 응답을 명시했다. 실제 OpenAPI를 다시 추출해 프론트 타입에 반영했다.
5. Test: 시행일 전/당일/이후 경계, 지급확정과 사전검증의 일치·읽기 전용, 사유 저장·조회, 집계 제외, DB 필수값 제약, 기존 계약 잠금 동시성, React 모달 표시를 검증했다.
