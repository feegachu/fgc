## 확인된 지연 원인

1. 화면을 이동해도 이전 문서의 fetch 요청 일부가 테스트의 in-flight 목록에 남았다. 진단에서는 검증 실행 API 6개가 계약 상세에서도 남아 매 settle 호출마다 최대 10초를 기다리는 현상을 확인했다. 기존 trace 한 역할 구간에서 100ms 대기 2,397회, 약 245초가 집계됐다.
2. response 헤더를 받은 시점에 request.sizes()를 호출하고 finish에서 Promise.all로 기다렸다. 본문 수신 도중 이동·취소된 요청의 측정이 끝나지 않으면 모든 화면을 순회한 뒤에도 완료되지 않았다.
3. 별도 환경 요인: macOS 전원 로그에 저전력·덮개 닫힘·유휴 잠자기가 반복 기록됐다. 전체 실행 중 Docker 명령 시간 초과, 스크린샷 및 context 종료 지연 등이 발생했다. 이 실행은 76개 통과·6개 실패로 보존하며 성공으로 간주하지 않는다. 정책 도움말 버튼 대기 실패도 후속 전체 재실행에서 재현되지 않았으므로 제품 결함으로 단정하지 않는다.

## 수정

- 새 메인 문서 요청이 시작될 때 이전 문서의 in-flight 집합을 비우고 새 요청을 추적한다. 하위 프레임 이동은 집합을 비우지 않는다.
- 늦게 끝난 이전 요청이 현재 요청 집합을 지우지 않고, 현재 문서와 하위 프레임 요청은 계속 기다리는 회귀 검사를 추가했다.
- 전송량 측정은 requestfinished 이후에만 수행한다. response 시점의 방문 기록을 WeakMap으로 연결해 다른 화면으로 전송량이 귀속되지 않게 했다.
- 미완료·측정 실패 요청은 전송량 보고서의 `미측정 요청 수`에 남겨 0바이트로 오해하지 않게 했다.
- 역할·경로 진행 로그를 남긴다. 문구 순회는 동영상 대신 문구/전송량 첨부·trace·실패 스크린샷을 사용한다.
- 제품 기능, 문구 합격 기준, 순회 역할/경로, timeout, retry 조건은 완화하지 않았다.
