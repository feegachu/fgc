# 초회 재무 스냅샷 정정 정책 (#389)

FUN-018 계약 저장과 FUN-063 차익거래 계산이 공유하는 정책이다. 운영정책서 제7조의 수기 등록 가정을 확장하며, 계약·차익거래 담당자는 PR에서 정정 대상과 조회 우선순위를 검토한다.

## 정정 대상과 저장

- 업무키는 `(contract_id, as_of_date, surrender_value_type)`이고 그 안에서 `snapshot_version`을 1부터 증가시킨다. 최초/기존 행은 버전 1, 정정 행은 직전 행의 `previous_snapshot_id`를 기록한다. 이전 행은 수정·삭제하지 않는다.
- 계약 수정은 현재 계약일의 `EXPECTED_TABLE` 최신 행이 `source_ref=MANUAL_CONTRACT_INITIAL`, 계약차월 1, 환급금·환급률표 NULL인 합성 초회 자료일 때만 보험료 정정을 추가한다. 누적 납입액이 초회보험료와 같으면 아무것도 추가하지 않는다. 금액의 소수 자리 표기 차이도 정정 사유가 아니다.
- 같은 업무키에 시드·정규화 적재분 등 다른 출처가 있으면 합성 정정으로 대체하지 않는다. ACTUAL과 후속 월별 자료도 계약 보험료로 갱신하지 않는다. 이번 작업은 자료 적재 API나 전체 과거 재계산을 추가하지 않는다.
- 현재 계약일의 EXPECTED_TABLE 행이 없으면 기존 수정 경로처럼 최초 합성 행을 보정한다. ACTUAL 행이 함께 있으면 조회에서 ACTUAL이 우선한다. 이후 월별 자료가 있더라도 초기 기준일 자료를 보정할 수 있지만 월별 행은 그대로 유지한다.
- 계약일을 앞/뒤로 변경하면 변경된 계약일의 업무키로 최초 행 또는 필요한 정정을 추가한다. 옛 날짜의 행은 보존한다. 동일 날짜로 돌아올 때도 해당 날짜의 최신 값과 같으면 추가 버전을 만들지 않는다. 충돌 회피 목적으로 업무 기준일을 현재 날짜로 바꾸지 않는다.
- 계약 행 잠금 뒤 별도 SQL로 최신 버전을 조회한다. 계약 변경 flush → 정정 추가 → 스케줄·한도·감사 저장이 하나의 계약 수정 트랜잭션이다. 예외 시 모두 함께 롤백한다. 오래된 편집 토큰은 #431의 409 정책으로 거절하며 최신 토큰의 재요청만 처리한다.

## 차익거래 원천 선택과 재현

1. 검증 기준일 이하의 자료만 대상으로 한다. 수기 합성 초회 자료는 현재 계약일과 같은 기준일의 행만 계산 후보로 삼는다. 이전 계약일의 합성 행은 이력으로 보존하지만 현재 계약의 계산에 사용하지 않는다.
2. 동일 업무키에서 가장 큰 버전의 행을 선택한다. 최신 업무 기준일 → 같은 기준일의 ACTUAL 우선은 유지한다. 같은 기준일·ACTUAL 우선순위 안에서는 시드·적재·기타 자료를 수기 합성 초회 자료보다 먼저 선택하여 합성 정정의 새 ID가 실제 원천을 밀어내지 않게 한다(제7조의 적재분 우선 원칙). 그 뒤 기존처럼 스냅샷 ID 내림차순으로 자료를 결정한다. EXPECTED_TABLE/ESTIMATED 사이에는 새로운 유형 우선순위를 추가하지 않는다.
3. 과거 기준일을 다시 검증하면 지금 존재하는 최신 정정 버전을 사용한다. `as_of_date`는 업무 기준일이고 `created_at`은 기록 시각이며, 이번 작업은 기록 시각을 지정하는 과거 상태 조회 API를 만들지 않는다.
4. 당시 결과 재현은 저장된 `arbitrage_check.calculation_snapshot`의 금액·판정과 `financialSnapshotId`, `financialSnapshotVersion`, `previousFinancialSnapshotId`, `financialSnapshotSourceRef`를 사용한다. 새 수동 검증은 새 실행에 저장하므로 이전 실행의 계산 근거는 유지된다. 기존 확정 실행의 불변 규칙을 유지한다.

## 마이그레이션 및 호환성

`V44__financial_snapshot_correction_versions.sql`은 기존 모든 행에 버전 1을 부여하고 ID·금액·기준일·출처·생성 시각을 보존한다. UNIQUE는 업무키+버전으로 확장한다. 기존 INSERT는 기본값 1을 쓰므로 기존 업무키 중복의 `ON CONFLICT ON CONSTRAINT uq_contract_financial_snapshot DO NOTHING` 동작이 유지된다.

직전 버전 FK, 양의 버전/연결 CHECK, 같은 업무키의 연속 버전 검증 및 직전 버전의 단일 후속 UNIQUE로 교차 계약 연결·버전 건너뛰기·분기를 차단한다. 버전·직전 연결은 UPDATE할 수 없고 정정 이력에 참여한 행의 변경·삭제도 DB에서 거절한다. 최신 버전 조회 인덱스를 추가한다. 기존 적용 Flyway와 시드 SQL은 수정하지 않는다.

이미 정정 버전이 저장된 뒤 원래 3컬럼 UNIQUE로 되돌릴 수 없으므로 운영 복구 시 행을 삭제하는 다운 마이그레이션을 사용하지 않는다. 배포 전 백업을 확보하고 장애 시 추가 마이그레이션 또는 백업 복구로 대응한다. 구버전 애플리케이션은 정정 추가를 수행하지 못하므로 스키마와 애플리케이션을 함께 배포한다.
