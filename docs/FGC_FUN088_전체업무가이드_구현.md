## 구현 경계

- 대시보드에서 기준월·지급단계를 확인하고 새 계약, 기존 계약번호 또는 기존 지급 번호로 시작한다.
- 공통 셸이 안내를 유지한다. 계약·지급·검증·대사·예외 화면에서 사용자가 선택한 실제 식별자를 받아 기존 API로 검증한다. 진도·입력·토큰을 별도 저장하지 않는다.
- `settlement.end_to_end`의 논리 단계는 계약, 스케줄, 지급 초안, 사전검증, 지급 확정, 월 검증, 대사, 예외, 최종 확정의 9개다.
- 안내 버튼은 GET 조회와 등록된 화면 이동만 수행한다. 저장·스케줄 재생성·사전검증·확정·월 실행·대사·예외 조치는 기존 업무 버튼으로 직접 실행한다.
- 입력 변경은 강조를 중단하고 카드를 접는다. 미저장 상태의 안내 이동은 취소해 현재 입력을 보존한다. 화면·권한 변경 및 늦은 응답을 방어하며 종료/Esc는 입력을 지우지 않는다.
- 지급의 현재 입력·저장본·사전검증은 FUN-087 observer로 판단한다. 화면을 떠난 뒤 이전 사전검증 성공을 복구하지 않는다. 이미 CONFIRMED인 지급은 중복 확정으로 안내하지 않는다.
- 스케줄은 계약·지급단계·실제 ID와 CURRENT/OPERATIONAL·사용 중 상태를 확인한다. 4년/7년 예정·중단·지난 버전은 지급 흐름으로 연결하지 않는다.
- 월 검증의 월·MONTHLY·실제 선정 대상 및 COMPLETED/FINALIZED를 확인한다. CREATED/RUNNING/202는 완료가 아니며 FAILED는 기존 오류/재시작 안내로 남는다.
- 대사 이력을 실제 페이지 수에 따라 조회한다. 계약의 보험사·검증 실행 ID·월·지급단계를 대조한다. 대사 불일치 또는 미해결 예외가 있으면 예외로 분기하고 직접 조치·재검증·재대사 후 새 결과를 선택하게 한다.
- 최종 확정은 8개 checklist와 GA_ADMIN/SYSTEM_ADMIN 권한을 안내한다. 실제 FINALIZED 조회만 전체 완료로 판정한다. SETTLEMENT에는 인계를 안내하고 역할을 바꾸지 않는다.

## 남은 API 제약

신규·기존 계약부터 대사 불일치까지의 시나리오와, 원천 정정부터 최종 확정·가이드 완료까지의 시나리오를 분리해 실제 서버에서 검증했다. 모든 예외 유형·보험사 조합의 업무 인수를 의미하지는 않는다.

기존 월 검증 상세는 선정 대상 최대 200건만 반환한다. 그 안에서 현재 계약의 SELECTED를 확인하지 못하면 가이드를 멈추며, 누락을 선정으로 추정하지 않는다. 200건 밖의 계약까지 지원하려면 기존 API의 대상 조회 경계에 대한 후속 결정이 필요하다. 별도 계산·진도 DB나 임의 API를 추가하지 않았다.

현재 입력은 안내 이동을 취소하는 방식으로 보호하며, 페이지를 떠난 입력을 복원하는 전역 폼 보존 기능은 추가하지 않았다. 작업월 변경은 새 안내 선택 화면으로 돌아가고 기존 진도를 자동 재사용하지 않는다.

검증 환경은 전용 PostgreSQL 17과 e2e 서버 프로필이다. 테스트 종료 시 fixture로 복원하고 전용 컨테이너·볼륨을 제거했다. 증거는 로컬 `deliverables/fun088-real-server-e2e/`에 보관하며 커밋 대상에서 제외한다.

## PR #759 리뷰 반영 (2026-10-29)

- 월 검증 생성·실행은 SETTLEMENT/SYSTEM_ADMIN, 예외 조치·원천 정정은 SETTLEMENT/GA_ADMIN/SYSTEM_ADMIN에게 인계한다. 권한 없는 단계에서 쓰기 대상 강조를 중단하고 필요한 역할을 표시한다. 이미 완료된 월 검증은 결과 선택으로 이어갈 수 있다.
- 정정 지급을 선택하면 이전 검증·대사·예외 선택을 모두 해제한다. 같은 안내 세션에서 무효화한 이전 검증 실행을 다시 선택해도, 재대사가 일치하거나 FINALIZED여도 완료 근거로 인정하지 않는다. 새 월 검증을 선택·실행한 뒤 재대사 결과를 확인한다.
- 새 검증 목록으로 이동할 때 카드를 접어 생성·실행 버튼을 가리지 않게 했다.
- 신규 계약 E2E의 보험회사 선택은 실제 native select를 사용한다. 상품·설계사는 검색형 선택을 유지한다.
- 최종 검증: 프런트 725 통과·5 제외, 빌드·ESLint·E2E 타입 검사 통과. 분리된 Spring Boot/PostgreSQL 17 실서버 E2E 3개 통과(정정·최종 확정 28.4초, 기존 계약 17.9초, 신규 계약 24.1초).
