원본 이미지는 실제 운영 서버 캡처가 아니다. 원본 Thymeleaf의 정적 HTML/CSS를 동일 React 셸 안에 렌더링하고 반복 행·권한 로딩 안내·페이지 푸터를 빈 상태에 맞춰 제거했다. 보험회사 로딩 완료와 실행/일괄 생성 비활성을 같은 상태로 설정했다. 원본 JS나 서버 렌더링을 실행하는 검증은 아니다. React 데이터는 합성 API 응답으로 고정했으며 개인정보가 없다.

`reconciliation-layout.spec.ts`는 위 원본과 React의 폼, 입력 필드 3개, KPI 5개의 위치/폭/높이, 결과 영역 위치/높이, 이력 시작 위치를 2px 허용 오차로 비교한다. 세 폭 모두 통과했고 화면 전체의 가로 넘침도 없다. 표는 원본처럼 내부에서 가로 스크롤한다. 작은 화면에서는 결과 라벨·선택·체크박스가 줄바꿈된다.

## 복원 내용과 수치 범위

- 실행 폼 중첩 테두리 제거, 필드 폭/정렬/필수 별표, 조회 테두리와 검색·실행·일괄 아이콘 복원.
- 지급단계 별표는 표시만 복원했다. 전체 단계의 과거 이력 조회는 허용하며 실제 실행 조건 검사와 권한은 유지한다.
- 동일 높이 KPI 5개, 일치율 한 자리와 접이식 계산 도움말, 차액의 값/원 단위 분리.
- 결과 필터를 헤더로 이동하고 원본 12열 폭·여백·빈 영역·tfoot 합계 복원.
- 무필터 합계는 서버 실행 전체 summary다. 유형 또는 불일치만 필터가 있으면 현재 서버 페이지에서 표시되는 행만 합산하고 ‘이 페이지 합계’로 표시한다. 서버 페이지 전체를 클라이언트에서 순회하지 않는다.
- 페이지 합산은 운영정책서 제17조의2에 따라 상세행마다 원 단위 HALF_UP 반올림한 뒤 BigInt로 더한다. 셀 표시와 합계는 같은 반올림 함수를 사용하며 음수는 절댓값을 반올림한 뒤 부호를 복원한다. 예를 들어 500.49원 두 행은 각각 500원, 합계는 1,000원이다. 무필터는 서버 summary를 그대로 사용한다. 누락 금액은 0으로 보정하지 않고 ‘—’로 표시한다. JSON 숫자로 이미 전달된 값의 전송 이전 정밀도까지 복원하지는 않는다.
- 미선택은 0 합계, 조회 중/실패는 ‘—’이며 안내를 구분한다. 현재 페이지에 불일치가 없더라도 전체 KPI와 다른 페이지 이동을 유지한다.

## 페이지네이션 연계

#556/#559 및 PR #558/#560은 확인 시점에 미병합이다. 공통 Pagination의 그룹 이동 방식은 변경하지 않았다. 이 화면에서는 0/1페이지의 컨트롤을 숨기고 기존 위치의 하단 우측으로 배치하며 결과/이력 페이지 상태는 독립적으로 유지한다. PR #560 병합 시 RECO-W01 호출부와 로컬 푸터 스타일을 함께 확인해야 한다.

## PR #577 반올림 리뷰 보완

초기 구현의 합산 후 반올림을 행별 HALF_UP 후 합산으로 수정했다. 0.49/0.50 경계, 양수·음수·상쇄, 큰 금액 문자열, 누락 금액과 실제 행/tfoot 표시 일치를 회귀 테스트로 검증한다. 서버의 두 주요 매칭 경로(InsurerGaReconciliationMatcherImpl, GaFcReconciliationMatcherImpl)는 이미 원천행을 MoneyUtil.roundWon으로 반올림한 뒤 합산함을 코드에서 확인했다. MoneyUtil.roundWon은 BigDecimal.setScale(0, HALF_UP)을 사용한다. 무필터 서버 summary는 그대로 유지하며 기존 DB 전체에 소수 금액이 없는지에 대한 데이터 감사는 수행하지 않았다.

보완 후 대사 관련 Vitest 41개 통과.
