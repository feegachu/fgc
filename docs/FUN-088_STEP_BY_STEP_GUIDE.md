# FUN-088 전체 업무 가이드 — 단계별 설명

2026-11-04. 기존 9개 업무 단계를 유지하고, 각 업무 안에서 설명을 한 항목씩 이동하도록 확장했다.

## 표시와 진행 원칙

Demo의 공통 `useSpotlight`를 재사용한다. 현재 입력칸 또는 확인 영역만 강조하고 주변을 어둡게 하며, 대상 아래에 설명 카드를 배치한다. 페이지 끝 등에서 아래 공간을 확보할 수 없으면 카드가 화면 안에 머물도록 위치를 제한한다. 페이지 배율 확대나 타이머 자동 진행은 없다. ‘확인하고 다음 설명’은 설명만 이동하며 저장·검증·확정을 실행하지 않는다.

입력 중 자동으로 카드를 접지 않는다. 이전 설명·접기·펼치기는 입력과 현재 설명 위치를 보존한다. 검색 입력은 실제 선택 값과 구분한다. 필요한 입력, 대상 누락·중복·숨김은 다음 설명을 막는다. 다른 계약·스케줄·정산월로 이동하면 기존 대상과의 불일치를 안내한다.

### 세부 안내 대상 오류와 복구 (2026-11-05)

- 처음 나타날 대상은 최대 5초 기다린다. 준비 시간이 지나거나 대상이 중복되면 세부 안내를 PAUSED로 중단하고 원인을 표시한다. 이미 찾은 대상이 사라지거나 숨겨져도 즉시 중단한다.
- 화면이 복구되어도 자동 진행하지 않는다. [다시 찾기]로 현재 설명의 대상을 재확인한다. 이전 설명·종료는 계속 사용할 수 있으며 입력값은 지우지 않는다.
- 지급 입력 안내와 나머지 업무 설명은 같은 대상 확인 훅을 사용한다. 단계 변경·비활성화·종료 시 이전 타이머와 이벤트 구독을 정리한다.
- 프런트 빌드에 `walkthrough-bindings.test.ts`를 포함한다. 실제 단계 카탈로그를 화면 JSX 선언과 대조하며 계약 금액 입력 함수, 귀속행의 동적 ID, 최종 확정 조건도 검사한다. 조건부 표시·실제 마운트 중복은 런타임 및 회귀 테스트로 함께 검증한다.

검증: 관련 가이드·스케줄 368건, 최종 세부 안내 회귀 98건 통과(서로 중복되는 집합). 빌드 내 도움말·연결 검사 59건, production build, lint 통과. Chrome 15245의 실제 로그인·계약 등록 안내에서 임시 대상 중복/숨김, 5초 초과, 명시적 재시도, 입력 보존 및 다음 설명 이동을 확인했다. 테스트용 DOM 변경은 원복했고 업무 저장 API는 실행하지 않았다. 전체 9단계 실서버 E2E 재실행 결과는 아니다.

## 업무별 설명

| 업무 | 세부 설명 |
|---|---|
| 계약 등록 | 계약일 → 보험회사 → 판매 상품 → 계약번호 → 설계사 → 납입주기 → 주기 보험료 → 초회 보험료 → 월납환산 보험료 → 납입기간 → 직접 저장 → 상세에서 결과 확인 |
| 예상 스케줄 확인 | 계약·지급단계 → 회차·귀속일 → 항목·금액 → 사용 중인 버전 → 스케줄 확인 완료 |
| 지급 초안 저장 | 지급단계 → 정산월 → 수령인 → 수수료 항목 → 금액 → 업무키 → 귀속행별 계약·날짜·금액·산입 여부·제외 증빙 → 행 추가 → 합계 검토 → 직접 저장 |
| 사전검증 | 저장 대상 → 귀속·합계 → 직접 사전검증 → 결과·차단 사유 |
| 지급 확정 | 최신 사전검증 → 확정 귀속 → 실제 확정과 확인창 → 목록에서 서버 상태 확인 |
| 월 통합검증 | 검증월 → 월간 유형 → 생성/기존 실행 선택 → 실행 정보 → 진행 상태·실행 → 대상 계약 → 계산 완료 |
| 대사 | 정산월 → 지급단계 → 보험회사 → 실행/기존 결과 → 실행 이력 선택 → 일치·불일치 결과 |
| 예외 처리 | 조회·선택 → 검출 근거 → 허용 조치 → 사유 → 증빙 → 직접 처리 저장 → 원천 정정·새 검증·새 대사 연결 |
| 최종 확정 | 실행 대상 → 아래 8개 조건을 각각 강조 → 권한·잠금 경고 → 실제 확정과 확인창 → 서버 FINALIZED 확인 |

최종 확정 8개 조건은 서버 체크리스트 순서대로 계산 완료, 차대 일치, 긴급 미처리 예외, 정책 없음·중복, 귀속합계, 상세·요약 합계, 최신 실행, 이미 확정된 실행 유무를 각각 설명한다.

## 서버 결과와 예외

- 마지막 ‘현재 결과로 이어서 안내’ 또는 ‘저장 결과 확인 · 다음 업무’에서 기존 서버 조회·판정을 유지한다. 설명을 읽었다는 사실로 업무를 완료 처리하지 않는다.
- 스케줄 확인은 읽기 확인이며 예정 생성·지급 확정이 아니다. 4년·7년 예정은 현행 지급 흐름에 연결하지 않는다.
- 확정 권한을 바꾸거나 실패·미해결 예외를 우회하지 않는다. 최종 확인창은 기존 업무 UI에서 직접 조작한다.
- 원천 정정으로 예외가 OPEN 목록에서 사라지면 기존 결과를 다시 조회한다. 서버에서 기존 지급 CANCELLED가 확인되면 정정 후 확정 지급 연결 안내를 표시한다. 사라진 예외 입력을 억지로 찾거나 완료 처리하지 않는다.
- 전체 업무 가이드는 계약 한 건 기준이다. FUN-087 다중 계약 지급 지원과 구분한다.
- 새로고침·종료 후 진행 복원은 추가하지 않았다. 재진입 시 서버 상태로 시작 대상을 판단한다.

## 수동 확인

1. 시연 환경에서 정산 계정으로 로그인하고 대시보드의 ‘전체 업무 가이드’를 연다.
2. 신규 등록은 계약번호를 비워둔다. 기존 계약은 `FGC-FGL01-202607-0002`를 입력한다. 정산월은 `2026-07`, 지급단계는 `GA → 설계사`로 확인한다.
3. ‘안내 시작’을 누르고 각 설명에서 실제 강조 대상이 하나인지 확인한다. 다음은 반드시 ‘확인하고 다음 설명’으로 이동한다.
4. 검색어만 입력한 상태에서는 실제 결과 선택과 구분되는지, 미입력 상태에서 다음이 잠기는지 확인한다.
5. 접었다 펼쳐도 입력과 설명 위치가 유지되는지 확인한다.
6. 저장·실행·확정은 업무 화면 버튼으로 직접 수행한다. 마지막 결과 확인 버튼으로 다음 업무를 안내받는다.
7. 정정 전 검증 실행을 재사용하거나 다른 계약/정산월을 선택했을 때 진행이 차단되는지 확인한다.
8. 최종 확정은 권한 있는 계정에서 서버 8개 조건과 실제 FINALIZED 결과를 확인한다.
