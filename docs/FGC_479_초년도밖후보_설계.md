# #479 초년도 밖 지급 후보 제외

## 문제와 결정 사유

최신 develop에는 후보 금액을 초년도 기간으로 거르는 합산이 이미 있다. 남은 문제는 기간 밖 후보도
룰셋 조회·스케줄 판정·기존 미해결 한도 위반 게이트를 거쳐 지급 확정을 차단할 수 있다는 점이다.
귀속일이 계약일+12개월 이상인 후보는 지급예정일도 같은 종료일 이상인 경우 해당 한도 검증 경로에서 제외한다. 계약일 전 귀속은 입력 오류를 유지한다.

이슈가 확정한 일 단위 attribution_date 기준을 따른다. 지급 회차가 12회차 이내라도 귀속일이 기간 밖이면
제외한다. 회차 기준 법규 해석은 이 작업에서 새로 결정하지 않는다. Java plusMonths(12)는 PostgreSQL
INTERVAL '12 months'와 같은 경계를 사용한다. 2028-02-29 계약의 종료일은 2029-02-28이며 종료일은 미포함이다.

## 기록 위치와 기존 판정 보존

후보 제외는 계약 전체의 비적용 판정(#482)과 범위가 다르다. 초년도 밖 후보만 있는 지급에 새 NOT_APPLICABLE
cap_check를 만들면 기존 계약 한도 위반/사용률이 최신 판정에서 가려질 수 있다. 따라서 후보만 있는 지급은
사전검증 capExclusions와 확정 감사행으로 근거를 보존한다. 혼합 지급은 기존 cap_check에 포함 후보만 계산하고,
excludedCandidateAttributions 스냅샷과 EXCLUDED 상세에 제외 후보의 ID·금액·기간·사유를 남긴다.

계약의 기존 예외를 해결 처리하지 않는다. 동일 계약에 초년도 안 후보가 하나라도 있으면 미해결 위반 차단은 유지한다.
계약 미상인 위반과 후보에 없는 계약 위반은 안전하게 차단한다. 입력 합계·제외 증빙·배부근거·권한·멱등성 검사는 유지한다.
잠금 후 재조회한 계약일로도 미해결 위반 게이트를 다시 확인하여 계약일 변경 대기 중 우회를 막는다.

## 범위와 API

IF-API-24에 capExclusions 배열을 추가한다. 기존 필드를 변경하지 않는다. React 및 레거시 지급 화면에 제외 사유와
귀속일·초년도 종료일·제외액을 표시한다. OpenAPI와 생성 TypeScript 계약도 갱신한다.
배포 전 API 추가 사항은 api-change/FE 확인 대상으로 기록한다. V51(#482)과 독립적인 코드 수정이며 DB 마이그레이션은 없다.

## PR #542 날짜 모순 리뷰 보완

귀속일만 2년차로 두고 실제 지급예정일은 초년도에 둔 입력이 검증을 건너뛸 수 있다는 리뷰를 반영했다.
초년도 기간 자체는 귀속일 기준 `[계약일, 계약일+12개월)`을 유지한다. 정상적인 기간 제외를 허용하려면
`transaction_attribution.attribution_date`와 `commission_transaction.due_date`가 모두 종료일 이상이어야 한다.
귀속일이 초년도 안이면 지급예정일이 늦어져도 기존 한도 검증을 수행한다. 귀속일만 기간 밖이거나
지급예정일이 없으면 `CAP_REVIEW_REQUIRED` / `OUTSIDE_FIRST_YEAR_PAYMENT_DATE_INVALID`로 기록하고 CAP_002로 차단한다.
정산월은 실적월이므로 지급예정일을 대신하지 않는다. 이 차단 기준은 사용자와 합의한 수정 계획에 따른다.

기존 due_date를 내부 `ConfirmationData` 조회에 추가했다. 잠금 조회와 재조회가 같은 SQL·매핑을 사용하므로
confirm의 계약 잠금 이후 확인에도 같은 지급예정일이 적용된다. 새 컬럼·Flyway·시드 변경은 없다.
precheck와 confirm의 공통 귀속 검증을 사용하며, precheck 차단 사유와 확정 예외 이력에 귀속일·지급예정일·
초년도 종료일을 담는다. 모순된 후보는 capExclusions에 정상 제외로 표시하지 않으며 룰셋 계산으로 넘어가지 않는다.
비교용 baseline에도 같은 차단을 반영했다. API 응답 필드와 OpenAPI 형태는 그대로 유지한다.

기존 정상 통합 테스트의 지급예정일을 실제 귀속 시점에 맞춰 바로잡았다. 수정 전 초년도 지급예정일 및
누락 날짜 2개 PostgreSQL 재현 테스트가 모두 실패함을 확인했다. 수정 후 정상 종료일·윤년 경계,
지급예정일 누락·초년도 선지급·혼합 후보 차단·초년도 귀속의 지연 지급을 검증한다.
React 테스트도 날짜 모순 사유와 차단 단계를 표시하며 정상 제외 문구를 표시하지 않는지 확인한다.

날짜 검증 보완 최종 결과: 전체 백엔드 build 1,927개 중 1,915개 성공, 12개 조건부 건너뜀, 실패 0. 프론트엔드 전체 359개 성공·4개 조건부 건너뜀(지급 폼 30개 포함), TypeScript·API 정합성·변경 TSX ESLint/Prettier 통과. 기존 계약 경계 통합 테스트 2개의 지급예정일도 실제 2년차로 수정했다. 개발 DB 변경 없이 임시 PostgreSQL을 사용했다.
