# 피코 로컬 보완의 원격 반영

관련 이슈: #664. 기준: develop `ef9922cc`, 통합 PR #813 병합 이후.

로컬 점검 브랜치의 `4ddf4bdb`, `227e94fc`, `32f4a801`을 기준으로 실제 누락만 이식한다. 기존 브랜치 전체를 덮어쓰거나 통합 PR을 되돌리지 않는다.

| 항목 | 반영 방식 |
|---|---|
| 관리자 AI 호출 버튼 파란색 | 내부 버튼만 변경. 설계사 전용 보라색 스타일 유지 |
| 스팟라이트 하단 카드·진행선·이전/다음 | 세 안내 호스트에서 공유 스타일과 실제 대상 좌표 사용. 모달 포털·역할별 단계 필터는 유지 |
| AI 단계 수·번호 목록 | 선택된 업무의 현재 역할 허용 단계 수만 허용. 연속 목록 번호만 제거. NFKC·유니코드 숫자·금액·횟수·URL·완료 주장 검증 유지 |
| 가이드 중 후속 질문 | 명시적 챗봇 열기 신호로 안내를 일시정지. 지급·전체 흐름은 접고 대상을 보존. 다른 안내의 동시 실행 방지는 유지 |
| 저장 직후 가이드 맥락 | 같은 지급 건의 정상 저장 응답은 업무 상태에 반영. 가이드 완료 증거의 별도 검증 유지 |
| 신규 지급 ID 발급 후 안내 재개 | 최신 GET으로 저장 상태를 다시 확인하고 저장 단계로 재개 |
| AI 전체 흐름 진입 | `settlement.journey`를 기존 9단계 `settlement.end_to_end` 실행기에 연결 |
| 권한별 근거 필터·조회 역할 보호 | #813의 단계별 역할 필터 구현을 유지. 이전 로컬 필터로 교체하지 않음 |
| 시간 초과 안내·정정 지급 월/단계 검사·생성 JSON 줄바꿈 | 원격에 동등하거나 확장된 구현이 있어 중복 이식하지 않음 |

검증: 프런트 332개 통과, 서버 83개 통과(문서 출력 3개·실제 제공자 opt-in 2개 스킵), TypeScript·변경 파일 ESLint·Vite 빌드·기능 식별자 648개·업무 위치 자료 1103개 검사 통과. 합성 API를 연결한 실제 Chrome 1440/390px에서 카드 하단 간격 16px, 화면 안 배치, 버튼 색상, 채팅 입력 접근을 확인했다. 업무 쓰기와 외부 제공자 호출은 수행하지 않았다.

로컬 Docker Linux 엔진 파이프가 없어 계산 스냅샷 DB 통합 테스트 6개는 환경 기동 실패했다. 해당 검증은 PR CI 결과와 별도로 구분한다. 원격 브랜치·PR 등록은 develop 병합이나 외부 서버 배포 완료를 뜻하지 않는다.
