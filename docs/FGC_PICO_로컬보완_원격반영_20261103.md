관련 이슈: #664. 기준: develop `ef9922cc`, 통합 PR #813 병합 이후.

로컬 점검 브랜치의 `4ddf4bdb`, `227e94fc`, `32f4a801`을 기준으로 실제 누락만 이식한다. 기존 브랜치 전체를 덮어쓰거나 통합 PR을 되돌리지 않는다.

| 신규 지급 ID 발급 후 안내 재개 | 최신 GET으로 저장 상태를 다시 확인하고 저장 단계로 재개 |

검증: 프런트 관련 회귀, 서버 83개 통과(문서 출력 3개·실제 제공자 opt-in 2개 스킵), TypeScript·변경 파일 ESLint·Vite 빌드·기능 식별자 648개·업무 위치 자료 1103개 검사. 합성 API를 연결한 실제 Chrome 1440/390px에서 카드 하단 간격 16px, 화면 안 배치, 버튼 색상, 채팅 입력 접근을 확인했다. 이 시각 검증에서 업무 쓰기와 외부 제공자 호출은 수행하지 않았다.

원격 UI 회귀에서 모바일 사전검증 결과가 늦게 펼쳐질 때 확정 대상이 아래로 이동하는 현상을 재현했다. 대상과 카드뿐 아니라 업무 영역의 크기 변화를 관찰하고, 레이아웃이 변할 때 실제 스크롤 영역을 한 번 정렬한다. 사용자의 일반 스크롤은 안내 카드의 부착 좌표만 갱신한다. 기존 PC/390px 지급 확정 Playwright 회귀 두 건이 수정 후 통과했다. 이 테스트의 저장·확정 응답은 API fixture이며 실제 DB 쓰기가 아니다.

후속 확인: 관련 프런트 331개 통과 후 지급 가이드가 접혀도 부모 폼이 닫힐 때까지 소유권을 유지하도록 보완했다. 마지막 변경 대상 두 파일 67개가 통과했고, 신규 소유권 회귀를 포함한다. API fixture 기반 브라우저 UI 전체 97개, 최종 AI 활성 화면 PC/390px 배치·채팅 검증, TypeScript·변경 파일 ESLint·production build도 통과했다.

로컬 Docker Linux 엔진 파이프가 없어 계산 스냅샷 DB 통합 테스트 6개는 환경 기동 실패했다. 해당 검증은 PR CI 결과와 별도로 구분한다. 원격 브랜치·PR 등록은 develop 병합이나 외부 서버 배포 완료를 뜻하지 않는다.

## #830 리뷰 재검토

승인 ID 치환과 접힌 지급 가이드의 중복 진입 지적은 유효하며 `e638fc40`에서 수정했다. Sonar S6353 두 건은 기본 ASCII 숫자 의미를 유지하는 `\d` 표기로 간소화했다.

S5854의 CANON_EQ 제안은 시험 적용 시 기존 `전체 -9단계입니다.` 차단 회귀가 실패해 원복했다. 사용자의 보안상 문제가 되는 입력을 차단하라는 지시에 따라 해당 옵션은 반영하지 않고 기존 출력 검증을 유지한다. 등록되지 않은 단계 수·음수 단계·AI가 생성한 금액은 `INVALID_AI_OUTPUT`으로 차단하고 고정 안내로 대체한다. Sonar 이슈를 임의로 suppress하거나 오탐 처리하지 않는다.

실서버 실패 27건 중 26건은 변경 전의 10px 스팟라이트 좌표를 기대했다. 현재 승인 디자인의 8px 여백과 업무 영역·헤더 경계로 기대값을 갱신하되 기존 3px 미만 오차 조건은 유지했다. 나머지 1건은 CSS가 대화창 동안 전체 업무 카드를 `visibility:hidden` 처리하는데도 펼치기 버튼의 표시를 기대한 테스트였다. 대화 입력 후 창을 닫아 기존 선택·접힘 상태가 보존됐는지 검증하도록 수정했다.
