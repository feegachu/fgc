## #725 확인된 누락과 수정

1. 페이지 이동 시 이전 결과를 유지하지만 갱신 안내가 없었다. `aria-busy`와 상태 문구를 표시하고 갱신 중 상세 이동·CSV를 잠근다. 이전 페이지를 새 페이지의 확정된 조회 결과로 오인하지 않게 한다.
2. 초기화가 정렬·선택 ID를 남겼다. 기본 조건·첫 페이지·기본 정렬로 되돌리고 선택 ID를 해제한다. 정산월은 유지한다. 일반 검색은 정렬을 유지하며 선택만 해제한다.
3. 같은 조건에서 조회를 누르면 URL이 같아 재조회되지 않았다. 첫 페이지·동일 조건은 명시적으로 refetch한다. 조회/초기화가 생성·저장 API를 호출하지 않는다.
4. 목록에 4년·7년 예정 결과의 지급 확정 제외 안내가 없었다. 선택 조건 또는 조회 결과가 해당 체계이면 안내한다.
5. 누락 회차·행 수·총액을 대시로만 표시했다. 자료 없음을 명시하고 실제 0원·음수와 구분한다. 계산 미준비 상태를 자료 없음으로 추정하거나 가짜 수치를 만들지 않는다.

## #726 원천 사건 조회 연결

#831(FUN-028, head `65b09a0e`)과 그 위에 쌓인 #835(FUN-029, head `c4f61c0e`)가 OPEN임을 확인했다. 현재 develop에는 후속 작업 인프라와 V74 효과 저장 구조가 있지만 운영 보류/재개 처리기 구현은 이 PR들에 있다. 구현을 복제하거나 임의로 상태 전이를 추가하지 않았다.

- `ScheduleQueryRepository`는 같은 스케줄·계약의 저장된 회차 효과를 읽어 sourceStatusEventId를 채운다. 같은 회차의 최신 실제 상태 결과가 현재 상태와 같을 때만 반환한다.
- EXCLUDED, 지급 건 효과, 다른 계약의 사건은 제외한다. 최신 실제 결과가 현재 상태와 다르면 더 오래된 일치 기록으로 되돌아가지 않는다.
- 상세 회차 상태 옆에 서버가 반환한 원천 사건 번호만 표시한다. 사건 생성/상태 변경/금액 계산 쓰기는 없다.
- PostgreSQL 저장소 통합 테스트에서 기록 없음→HOLD→제외 기록→PLANNED 결과/상태 불일치→일치→다른 계약 기록 순서를 검증했다. 이 시험은 조회 계약을 검증하는 롤백 fixture이며 실제 보류/재개 worker E2E가 아니다.
- 목록·상세 프런트 30개, 저장소 통합 테스트 통과. 전체 서버 및 build/lint 최종 결과는 아래에 기록한다.

남은 의존 작업: #831→#835 통합 후 실제 처리기로 실효→부활을 실행하고, 계약 이력·IF89 효과·스케줄 원천 ID·보류/재개 대상/비대상·금액·정책을 대조한다. 이 검증 전 #726 CT-C02 전체 완료로 체크하지 않는다. 상세 영향 UI는 기존 #724/#719 계약과 함께 연결하며, 아직 제공되지 않는 IF89를 현재 브랜치에서 호출하지 않는다.
