# #556 대사 결과·실행 이력 페이지네이션 복원

> **#560 후속 결정:** 간단한 현재/전체 UI 대신 공통 숫자·5페이지 묶음 방식으로 변경했습니다. 기존 하단 우측 위치는 유지합니다. 아래 내용과 이미지는 초기 구현 이력입니다. 최신 화면은 [#559 기록의 후속 변경](../559/README.md#560-후속-변경-대사-숫자-페이지네이션-통일)을 확인하세요.

> 후속 통합: 이 문서는 초기 로컬 작업 기록입니다. 최종 공통 표시 조건·배치와 푸시 상태는 [#559 검증 기록](../559/README.md)을 기준으로 합니다. #550·#554는 현재 병합되어 있습니다.
상위 추적 이슈: #552. 이슈 생성 및 로컬 수정·검증까지 진행했으며 PR은 생성하지 않았습니다.

## 구현

대사 화면에서 공유하는 ReconciliationPagination을 추가하여 결과·이력 모두 `‹ 현재 / 전체 ›` 형태로 표시합니다.

- 개별 숫자 버튼과 테두리를 없애고 아이콘 화살표와 가운데 현재/전체 표시 사용
- 하단 우측 정렬, 구분선 및 여백 적용
- 전체 2페이지 이상일 때만 표시 (0·1페이지는 숨김)
- 결과 resultPage와 이력 page는 각각 독립적으로 한 페이지씩 이동
- 첫 페이지 이전·마지막 페이지 다음 버튼 비활성
- 검색조건·정산월·선택한 실행·결과 유형·불일치만 상태 유지
- 두 영역의 navigation 이름을 구분하고 aria-live로 현재 페이지 안내
- 비활성 hover의 글자색·배경 강조를 방지

계약·수수료 지급·예외 목록의 숫자·5페이지 묶음 UI는 변경하지 않았습니다. 대사 영역은 icon-button을 사용하므로 #550의 pagination-button 스타일 수정에 의존하지 않습니다. 원본 Thymeleaf의 실행 이력은 이전·다음 텍스트였지만, 사용자 요청에 따라 결과와 이력 모두 같은 화살표 형태로 통일했습니다.

## 검증

- 대사 관련 테스트: 30 passed
- 전체 프런트엔드: 440 passed / 4 skipped (기존 조건부 skip)
- ESLint·TypeScript·Vite 운영 빌드·git diff --check 통과
- Chromium 실제 React + 테스트 API 응답으로 두 영역의 다음·이전 이동 및 첫·마지막 경계 확인
- 결과 페이지 변경 시 이력 page 유지, 이력 페이지 변경 시 결과 resultPage 유지 확인
- month·stage·insurer·runId·resultType·onlyMismatch 유지 확인
- 0·1페이지에서 양쪽 페이지 이동 UI 숨김 확인
- 비활성 버튼 hover 전후 색상·배경 유지, 375px에서 뷰포트 넘침 없음
- React 품질 점검: 기존 아이콘 버튼 재사용, 네이티브 disabled·접근성 이름·상태 안내, 새 데이터 조회·effect 없음

테스트 데이터로 촬영했으며 실제 DB 연동 검증은 수행하지 않았습니다. API·계산·DB 변경은 없습니다.
